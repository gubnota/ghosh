# Implementation Plan: M1.1 workspace foundation

Status: completed; approved and executed sequentially. Date: 2026-10-18.

## Delivered outcome

M1.1 is implemented in core + desktop shell with workspace UI, safe persistence,
typed/generated contracts, native Keychain boundary, Finder package association,
locked build tooling, licenses, README and a sequential CI definition. Local arm64
release bundle builds and runs. M1.2+ remains unimplemented.

Verification: 30 default Rust tests pass; the optional native Keychain round trip
also passed outside the restricted sandbox. Formatting, Clippy with warnings denied,
generated-contract freshness, TypeScript/Vite and application bundle build pass.
Interactive native smoke covered creation, save, external conflict with dirty draft,
reload confirmation, trust/reset, recent history, dialogs and cold/warm Finder open.
See TASK_LOG.md for environment and unexecuted release gates.

Refinements to the original plan below:
- Atomic no-replace staged publication replaces the proposed multi-file recovery
  journal: there is no visible partial package and no multi-file edit in M1.1.
  Crashed hidden stages are left inert; automatic cleanup/recovery is deferred.
- Anchored cap-std/rustix filesystem access strengthens path and publication checks.
- Native invalidation also uses bounded two-second configuration revision probes,
  added after a native notification was missed during the smoke test.
- A queue allocated before Tauri setup handles early macOS document-open delivery.
- Atomic cancellation + blocking workers are sufficient for this scope; structured
  async supervision/tracing is deferred until live operations exist.
- Local-storage limitations are documented; automatic synced-volume detection is
  deferred. There is no distributed-lock or arbitrary-editor filesystem CAS claim.
- Icons and generated schemas were added as required bundle/contract artifacts.
- Minimum macOS 14, remote CI and signing/notarization remain unverified/unconfigured.

The remaining sections retain the approved implementation plan as historical scope.

## Goal

Deliver the first compilable macOS 14+ arm64 Tauri 2 + React/TypeScript app that
creates and opens a `.ghosh` workspace, validates its manifest and node references,
round-trips unknown TOML fields, saves with conflict protection, watches external
edits, and displays honest workspace/trust/error states. Establish the Rust policy,
secret, operation and typed IPC boundaries needed by later increments.

## Baseline before implementation

Initial repository bbac06a contained only `.gitignore` (`.DS_Store`). This phase
added documentation only. There is no Cargo/frontend/Tauri project, runtime,
existing test suite or dependency lockfile to preserve. Proposed architecture is
in ARCHITECTURE.md; M1.1 is one increment of M1, not the whole remote-control app.

## Proposed approach

Create only `ghosh-core` and the desktop shell now. Use `toml_edit` with typed
projections, `serde`, `thiserror`, `tokio`/tokio-util and `notify`; generate DTOs with
`ts-rs` and document schemas with `schemars`. Use `uuid`/`ulid` identities and
`tracing` with secret-safe values. Concrete Keychain implementation lives in the
macOS shell; core owns SecretStore. Pick current compatible dependency versions
from their primary documentation when implementing and pin lockfiles/toolchain.

Opening is inert: no hooks/scripts/network calls. Keep a validated revision
snapshot, one writer lease per canonical package, unknown-field AST, hash-based
compare-and-swap save and external-change notifications. Workspace trust defaults
to untrusted/read-only for operations. Configuration edits require human UI intent;
read_only MCP policy and script execution grants are contracts only at this phase.
Never expose unimplemented action buttons as working services.

## Implementation steps

1. Bootstrap the two Rust packages and Vite/React shell with license/config files.
   Set minimum OS 14.0 and default aarch64-apple-darwin. Verify a minimal desktop
   build before adding persistence. Do not install runtimes/SSH/VLESS sidecars.
2. Add validated IDs, manifest/node models, structured errors and secret-safe
   wrappers. Enforce schema/version/path/reference constraints, including unknown
   newer schemas. Tests cover unknown-key preservation and malformed identities.
   Future profile/cert/recipe files remain opaque preserved files in M1.1 and cannot
   execute; each later service adds its typed validation before activation.
3. Implement WorkspaceService create/open/update, lossless AST patches, canonical
   path containment and workspace-ID/path ownership. Newly created package includes
   required directories and safe gitignore; persist no secret values. Verify
   creates, reopen, comment/key preservation, symlink/traversal and secret canaries.
4. Implement compare-and-swap atomic single-file persistence, app-owned lock,
   journal/recovery for multi-file create and debounced watcher. Verify external
   edit vs dirty local edit, invalid-file recovery, duplicate writer, cancellation
   during create/save and partial filesystem failure. No fabricated migration path.
5. Implement SecretStore macOS adapter and permission/context boundary; return
   scoped availability/reference information, never values, to UI. Use temporary
   test service IDs and ensure cleanup; locked Keychain tests may require manual
   interaction and are explicitly reported if not executed. No permission prompts
   are triggered just by opening a workspace.
6. Generate frontend DTOs and manifest/node schemas; wire explicit Tauri workspace
   commands/events with custom-command ACLs scoped to the local shell. Typecheck
   the actual generated outputs; test wrong revision/caller/path rejection.
7. Add welcome/create/open/recent/overview/trust/conflict UI, preserving a single
   shell/tab architecture. Add macOS Finder package-open handling. Verify keyboard
   access, dirty-state handling, permission/path diagnostics and reopen behavior.
8. Add README/CI and update six context files. Run the checks below; record real
   pass/failure/skipped results. Commit only coherent small increments if repository
   policy and user authorization permit; do not push/publish/sign with user keys.

  conflict, two workspace instances, unavailable Keychain, untrusted imported file.

No SSH/container/MCP conformance is claimed in M1.1; those are required in their
own increments. No additional UI unit suite for reversible presentation-only
changes; test meaningful persistence/policy behaviors and manually verify layout.

## Risks / edge cases

- No Rust toolchain/application dependencies were verified during documentation;
  environment setup or restricted network access can block builds and must be
  reported explicitly.
- macOS package/document opening and Keychain require native checks; mocks alone
  do not establish support. Signing/notarization needs credentials at release.
- File coordination is single-host/local-filesystem initially; synced/network
  packages are detected and warned about, with no distributed lock guarantee.
- User corrections in docs/ghosh-prompt.md are reflected in the schema: immutable
  UUID profile stores and the complete B1 mandatory approval set. Implementation
  fixtures must cover both positive samples and negative load/startup cases.
- Dependency setup may generate extra mandatory build artifacts; keep them scoped
  and explain additions, with no unrelated repository changes.

## Out of scope

M1.2+ SSH/engine/adapters/live remote runs, terminal emulator, native browser views,
tunnels/VLESS, certificates, JS/Python/Node execution, recorder, recipes, actual
MCP protocol server/client and Linux/Windows backends. Full product screen design
is documented separately and does not imply these features are implemented.
